## Problem Statement

stare.na renders one person's Are.na (312 channels) as a 3D galaxy — built as a gift for Tereza Slančíková, to give her an unexpected look at the clusters of her interests. The builder wants to keep the gift special while letting any Are.na user see their own galaxy. Priorities, in the builder's words: (1) "provide unexpected look at what clusters of interest [someone] has", (2) "explore deeply your are.na", (3) "space just looks quite cool like a representation of the embedding space". Personalization/gift-giving flow comes later.

## What Makes This Cool

Every embedding-map tool (Nomic Atlas, TensorBoard Projector, WizMap) treats the map as *analysis*. stare.na treats it as an *artifact* — a poster of someone's mind. The generalized version keeps that: paste your Are.na username, watch your own universe form. The compute delay (model download + embedding + UMAP in the browser) becomes the money shot: stars condense from a nebula into your clusters. Inherently screen-recordable, which is the shareability story.

## Constraints

- No compute servers: fetching, embedding (transformers.js MiniLM), and layout (umap-js) all run in the browser. v1 has zero server-side storage; a thin cache endpoint is allowed post-A only if shared-link demand shows up.
- Public channels only (no auth) in v1.
- Tereza's root-URL galaxy stays canonical and **behaviorally identical** — verified by the root-route regression e2e (the GalaxyView extraction and code splitting change bundles, so "byte-identical" is the wrong test; "a user can't tell" is the right one).
- The ML stack (transformers.js + onnxruntime WASM) is **route-level code-split**: dynamically imported on `/you` and `/:username` only. The root route's bundle stays free of it.
- Model weights (~25MB quantized ONNX, Xenova/all-MiniLM-L6-v2) are **self-hosted on the Vercel deployment**, not fetched from the Hugging Face CDN — no third-party availability dependency on the product's cold path. transformers.js caches the download in the browser automatically; do not build model caching.

## Premises (agreed)

1. Generalize the reveal, not the tool — poster-first, never an analysis UI.
2. Person #2 is an Are.na user; distribution is the Are.na community itself.
3. Zero-server is the right constraint at this scale.
4. Tereza's version stays special regardless of the multi-user path.

## Architecture (eng-review decisions)

- **GalaxyView extraction (1A):** Index.tsx's ~150 lines of shell wiring (search, panels, camera reset, overview button) become a shared `GalaxyView` component taking `(channels, loading/progress state, identity block)`. `Index` configures it with the static JSON + Tereza's intro/credit; `UserGalaxy` configures it with the worker pipeline + generic identity. No forking — every future UI fix lands once.
- **Worker protocol (2A):** a discriminated-union message contract: `resolving → fetching(page/total) → loading-model → embedding(i/n) → layout → done(Channel[]) | error(kind)`. One DM Mono status line renders during compute in A (B's narration plugs into the same seam). `worker.terminate()` on route unmount — no CPU burn after abandon. The protocol includes a **mock seam** so tests can drive the orchestrator without real inference.
- **Mobile gate (T2):** detect mobile / slow connection before starting compute → a designed interstitial ("galaxies are best forged on a desktop — proceed anyway?") with proceed-anyway. Distribution is Discord/community links, which are mostly phone clicks; the gate converts the worst first impression into an honest moment. Full mobile compute (WebGPU) is out of scope — and note: WebGPU embeddings are device-dependent, so enabling it later trades away the determinism guarantee. Written down so nobody trips it silently.
- **SidePanel Are.na URL (4A):** links become `https://www.are.na/channel/${channel.slug || channel.id}` — owner-independent, one line, correct on both routes. (Today's `are.na/tereza-slancikova/<slug>` 404s on anyone else's galaxy.)

## v1 Pipeline Spec (browser, Web Worker)

**Fetch plan:**
1. `GET api.are.na/v2/users/:slug` → user id (also validates the username).
2. `GET api.are.na/v2/users/:id/channels?per=100&page=N` — sequential (4 pages for 312 channels).
3. **Bounded block-title enrichment (T1):** for channels with empty descriptions ONLY, fetch first-page contents (`per=50`) for block titles — capped at ~60 requests, largest channels first (~30s). Cryptic-title + empty-description channels are the common case on Are.na; title-only embedding clusters *words*, not *interests*, and the concierge demand test runs the block-title pipeline — v1 must ship the product that was validated. Full per-channel contents fetch stays out (rate cliff).
4. SidePanel block previews stay lazy — `GET /v2/channels/:id/contents?per=6` on star click.
5. Model download starts in parallel with step 1.

**Embedding inputs:** `title` (weight 2.0) + `description` (weight 1.0) + enriched block titles (weight 1.5, from step 3) — same weights as [generate_embeddings.py](../../scripts/generate_embeddings.py). **The embedding-assembly module is written once in TS** and shared by the worker and the A2 bun script (below) — never two implementations of the same math.

**Layout parity (with spike — T3/D11):** umap-js `nComponents: 3`, `nNeighbors: 8`, `minDist: 0.3`, cosine distance, seeded RNG. Port [umap_reduce.py](../../scripts/umap_reduce.py) post-processing verbatim: size/emissiveIntensity formulas, top-3 cosine neighbors, normalization/centering. **Known risk:** umap-learn defaults to spectral initialization; umap-js initializes randomly and accepts no custom init — same params do not guarantee the same global structure. A **half-day spike inside Next Step 2** measures umap-js quality vs the Python output on the fixture, tests PCA-as-init workarounds, and prototypes the B enrichment transition. Its findings (including the fallback if parity fails) are written back into this doc before UI work depends on them.

**Determinism:** fixed seed + stable input ordering ⇒ same input data → same layout. (WASM inference is deterministic; WebGPU would break this — see mobile gate note.)

**Layout cache (7A):** computed `Channel[]` stored in IndexedDB keyed by `username + channel-count + updated-at hash`. Hit → instant render; miss → compute + store. Client-only; self-invalidates when their Are.na changes. **Expectation note:** active Are.na users invalidate often — this is a same-session/same-day convenience, not the sharing story. Instant shared links for strangers remain the B-era serverless cache.

**Error and degenerate inputs:**
- Unknown username → inline "no one here by that name" under the input, no navigation.
- 0 public channels → "your galaxy is still dark" empty state with a link to Are.na.
- < 30 channels → seeded Fibonacci-sphere fallback layout, semantic `neighbors` lines carry the meaning.
- 1000+ channels → cap at the most recently updated 750 with a visible note. (Sort-order assumption verified by the probe below.)
- Empty-title channels → skip embedding, place on the fallback sphere shell, dim.
- API failure mid-fetch → retry with backoff ×3, then partial-galaxy banner ("rendered 200 of 312 — retry").
- Navigate away mid-compute → worker terminated (2A).

**Routing:** `/:username` via react-router. The Vercel SPA rewrite **already exists** in [vercel.json](../../vercel.json) — no infra change. Username input lives at `/you` (minimal dark page, inline errors); root stays Tereza's with no added UI. Reserved from username matching **in the client-side matcher**: `/you`, `/data/*`, `/assets/*`, and current static files.

**API probe (Next Step 1, extended):** verify from a browser console — CORS on all three endpoints; `per=100` validity per endpoint; actual rate limits (the 500ms inter-page delay is invented politeness — if the real limit allows, drop it and save ~2s of the money shot); channel list sort order (the 750 cap depends on recency ordering).

## Testing (eng review — 19 paths, all planned)

Framework: vitest (unit) + Playwright (e2e). Test split (D12.3): **Playwright fixtures cover fetch/UI/error states** (api.are.na route-intercepted with recorded fixtures, including a real small account); **pipeline correctness lives in vitest** against `scripts/arena_raw.json` with precomputed embeddings through the worker protocol's mock seam. CI never runs real inference.

Unit (vitest):
- `arenaFetch`: pagination, backoff ×3, unknown user, zero channels, >750 cap + flag, mid-fetch partial, enrichment request cap + largest-first ordering.
- `embedText` (pure): weight assembly 2.0/1.0/1.5; empty description; empty title → skip flag.
- `layout` (pure): seeded determinism (run twice, assert identical); n<30 sphere fallback; size/emissive/neighbors match the **Python golden fixture**; output typechecks as `Channel[]`.
- Worker orchestrator (mock seam): progress event ordering; cancel mid-phase emits nothing further.
- SidePanel: lazy contents fetch on click; fetch failure → section absent, no crash; universal `/channel/` URL on both routes.

E2E (Playwright, fixture-intercepted — 6A):
- `/you` → valid username → progress phases → galaxy renders with labeled stars.
- Unknown username → inline error, no navigation.
- **REGRESSION (critical): root route renders and behaves identically after the GalaxyView extraction** — intro, search, select, panel, ← Galaxy reset, corner credit.
- Mobile gate: mobile viewport → interstitial shown, proceed-anyway works.

**Regression rule:** the GalaxyView extraction and the SidePanel URL change both touch Tereza's working page — their regression tests are non-negotiable requirements of milestone A, written alongside the change.

## Approaches Considered

### Approach A: "Your Galaxy" — minimal viable (CHOSEN as milestone 1)
The v1 Pipeline Spec above + GalaxyView extraction + worker protocol + mobile gate + cheap reveal (stars animate from seeded random positions to UMAP positions over ~4s, camera pull-back, labels fade in) + layout cache + the test suite. Effort M (human ~2-3 weekends / CC ~3-4 sessions). Risk low-medium — the spike de-risks the one real unknown.

### Approach A2: retire the Python pipeline (5A)
After A's fixture-parity test passes: run the shared TS pipeline in a bun script over `arena_raw.json`, regenerate Tereza's `channels.json`, verify visually, delete `scripts/*.py`. One implementation of the math, and the gift provably runs on the same code path as everyone else. (CC ~15min when due.)

### Approach B: "The Reveal" — declared destination (milestone 2)
Live epoch-by-epoch UMAP condensation choreographed with narration beats; post-reveal constellation summary (3 biggest clusters auto-named). **Enrichment reality check (T3):** UMAP is not incremental — "background enrichment refining the layout" is actually *recompute + animated transition between layouts* (stars fly to new positions), or it doesn't ship; the D11 spike prototypes this. Optional post-A if shared-link demand appears: thin serverless cache endpoint (the one storage exception, with write-abuse consideration).

### Approach C: "Two Galaxies" — later
`/you+me` merges two usernames into one space. Ruled *later*, not out: meaningless until A proves anyone shows up, and it doubles fetch+compute per visit.

## Recommended Approach

**A now (with spike), A2 right after, B staged, C after.** User's words: "agree with A first while targeting B but C is also very cool, will do that later."

## Success Criteria

- A stranger can paste their Are.na username on desktop and see their own labeled galaxy in under ~90s, zero manual pipeline steps.
- Same input data → same layout on every visit (fixed seed, WASM backend).
- Tereza's root-URL experience is **behaviorally identical** to today, proven by the root-route regression e2e.
- **At least 3 real Are.na users told the builder they generated their own galaxy** (measurable without analytics; there is no server to count for us).
- Mobile link-clickers see the designed gate, never a dead spinner.
