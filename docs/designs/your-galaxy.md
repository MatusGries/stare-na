## Problem Statement

stare.na renders one person's Are.na (312 channels) as a 3D galaxy — built as a gift for Tereza Slančíková, to give her an unexpected look at the clusters of her interests. The builder wants to keep the gift special while letting any Are.na user see their own galaxy. Priorities, in the builder's words: (1) "provide unexpected look at what clusters of interest [someone] has", (2) "explore deeply your are.na", (3) "space just looks quite cool like a representation of the embedding space". Personalization/gift-giving flow comes later.

## What Makes This Cool

Every embedding-map tool (Nomic Atlas, TensorBoard Projector, WizMap) treats the map as *analysis*. stare.na treats it as an *artifact* — a poster of someone's mind. The generalized version keeps that: paste your Are.na username, watch your own universe form. The compute delay (model download + embedding + UMAP in the browser) becomes the money shot: stars condense from a nebula into your clusters. Inherently screen-recordable, which is the shareability story.

## Constraints

- No compute servers: fetching, embedding (transformers.js MiniLM), and layout (umap-js) all run in the browser. v1 has zero storage; a thin cache endpoint is allowed post-A only if shared-link demand shows up.
- Public channels only (no auth) in v1.
- Tereza's galaxy stays canonical at the root URL, untouched.
- The renderer keeps consuming the existing `Channel[]` schema. One acknowledged renderer change: SidePanel lazily fetches block previews on star click instead of reading a pre-baked `blocks[]` (see Fetch Plan).

## Premises (agreed)

1. Generalize the reveal, not the tool — poster-first, never an analysis UI.
2. Person #2 is an Are.na user; distribution is the Are.na community itself.
3. Zero-server is the right constraint at this scale.
4. Tereza's version stays special regardless of the multi-user path.

## Cross-Model Perspective (Claude subagent cold read)

- **Coolest unconsidered version:** render the UMAP optimization live, epoch by epoch (umap-js supports stepwise fitting) — the user watches clusters *emerge*. Converts the compute delay into the #1 whoa moment. Runner-up: two-username merge ("your galaxy + mine").
- **Key tell:** "unexpected clusters of your own interests" ranked first — a mirror-maker's goal, not a tool-builder's. Optimize the first 60 seconds ruthlessly; everything else is secondary.
- **50% off the shelf:** transformers.js (Xenova/all-MiniLM-L6-v2, quantized, ~25MB, same model as the Python pipeline) + umap-js. The other 50%: browser Are.na fetch with backoff, Web Worker orchestration with progress, **determinism** (a galaxy that reshuffles every visit never feels like yours), small-account degradation, reveal choreography.
- **Breaks first:** Are.na rate limits if block contents are fetched upfront. **Breaks second:** UMAP degenerates under ~30 channels.

## v1 Pipeline Spec (browser, Web Worker)

**Fetch plan (312-channel account ≈ 5 requests, seconds not minutes):**
1. `GET api.are.na/v2/users/:slug` → user id (also validates the username).
2. `GET api.are.na/v2/users/:id/channels?per=100&page=N` — sequential, ~500ms between requests (4 pages for 312 channels).
3. **No per-channel contents fetch during generation.** Block previews are fetched lazily — `GET /v2/channels/:id/contents?per=6` on star click, one request per click, feeding SidePanel.
4. Model download (~25MB quantized ONNX) starts in parallel with step 1 — on desktop broadband the fetch and the download finish together.

**Embedding inputs — a decided trade-off:** v1 embeds `title` (weight 2.0) + `description` (weight 1.0) only. This is a **known cluster-quality regression** vs the gift pipeline, which also embeds all block titles (weight 1.5) — many Are.na channels have empty descriptions, so their position rests on the title alone. Accepted for v1 because block-title fetching costs ~1 request/channel (~2.5 min for 312 channels at polite delays). Milestone B adds **background enrichment**: after the initial galaxy renders, stream block titles in and let the layout refine — which doubles as reveal choreography.

**Layout parity:** port `umap_reduce.py` behavior, not just the algorithm: umap-js with `nComponents: 3`, `nNeighbors: 8` (the <30-channel fallback below makes an adaptive clamp moot), `minDist: 0.3`, cosine distance, seeded RNG (umap-js accepts a custom `random` fn). Then port the post-processing verbatim: per-channel `size`/`emissiveIntensity` formulas, top-3 cosine-similarity `neighbors`, normalization/centering. Output must typecheck against `src/types/channel.ts` with `blocks` optional/empty (lazy-loaded). Visual parity with the Python pipeline's look is a goal; Next Step 2 compares the two on the same fixture.

**Determinism:** fixed seed + stable input ordering ⇒ same input data → same layout, no storage needed. (If the user's channels change, the galaxy legitimately changes.)

**Error and degenerate inputs:**
- Unknown username → inline "no one here by that name" state under the input, no navigation.
- 0 public channels → "your galaxy is still dark" empty state with a link to Are.na.
- < 30 channels → UMAP output degenerates; fall back to a seeded Fibonacci-sphere layout with semantic `neighbors` lines carrying the meaning.
- 1000+ channels → cap at the most recently updated 750 with a visible "showing your 750 most recent channels" note; keeps fetch and embed time bounded.
- Empty-title channels → skip embedding, place on the fallback sphere shell, dim.
- API failure mid-fetch → retry with backoff ×3, then partial-galaxy banner ("rendered 200 of 312 — retry").

**Routing:** `/:username` via react-router; add Vercel SPA rewrite (all paths → index.html) so deep links work; reserve `/data/*`, `/you`, and future static paths from username matching. **The username input lives at `/you`** — a minimal dark page with the input and the inline error states; the root URL stays Tereza's galaxy with no added UI (byte-identical). Discovery of `/you` happens through shared links and community posts, per the Distribution Plan.

## Approaches Considered

### Approach A: "Your Galaxy" — minimal viable (CHOSEN as milestone 1)
The v1 Pipeline Spec above, plus a cheap reveal: stars animate from seeded random positions to UMAP positions over ~4s, camera pull-back, labels fade in. Effort M (human ~2 weekends / CC ~2-3 sessions). Risk low — additive route; the only renderer change is SidePanel lazy block fetch.

### Approach B: "The Reveal" — declared destination (milestone 2)
Everything in A plus: live epoch-by-epoch UMAP condensation choreographed with narration beats ("312 channels… finding the shape of your mind…"); background block-title enrichment refining the layout after first render; post-reveal constellation summary — the 3 biggest clusters auto-named from channel titles, delivering the "unexpected look" in words as well as shape. Effort L. Risk medium — choreography and cluster naming need taste iterations (lazy auto-naming reads as cringe). Optional post-A extra if shared-link demand appears: thin serverless cache endpoint for instant loads (the one storage exception to the zero-server constraint, with write-abuse consideration).

### Approach C: "Two Galaxies" — later
`/you+me` merges two usernames into one space; shared clusters gravitate together. Ruled *later*, not out: meaningless until A proves anyone shows up, and it doubles fetch+compute per visit.

## Recommended Approach

**A now, B staged, C after.** A is a strict subset of B — nothing thrown away. User's words: "agree with A first while targeting B but C is also very cool, will do that later."

## Open Questions

- Are.na API CORS behavior from the browser for `users/:slug`, `users/:id/channels`, `channels/:id/contents` — verify with a live probe before building the fetch layer (Next Step 1).
- Mobile: is a 25MB model download acceptable on cellular, or does mobile get a "view a sample galaxy / come back on wifi" path?
- Cluster auto-naming approach for B (top-TF-IDF terms vs tiny on-device summarization) — taste call deferred to B.

## Success Criteria

- A stranger can paste their Are.na username and see their own labeled galaxy in under ~90s on desktop, zero manual pipeline steps.
- Same input data → same layout on every visit (fixed seed, no storage).
- Tereza's root-URL experience is byte-identical to today.
- At least 3 real Are.na users (not the builder) have generated their own galaxy and reacted.

## Distribution Plan

Web service on the existing Vercel deployment — `/:username` routes on stare-na.vercel.app (or a proper domain later). No packaging, no CI changes beyond the existing auto-deploy on push. Discovery: shared directly in the Are.na community (channels, Discord, word of mouth) — see The Assignment.
